# Как включить настоящий ИИ в FINANCE OS 4.0

## Почему одного ZIP на GitHub недостаточно

Пакет Update обновляет интерфейс и локальную логику. Пакет AI-Server — отдельная программа, которая обращается к OpenAI, хранит ключ только на сервере и проверяет доступ/лимиты запросов. GitHub Pages не запускает этот Python-сервер.

**Сервер в этом выпуске не развёрнут. Ключ и модель не заданы, живой запрос к OpenAI не выполнялся.** Не отправляйте ключи в чат и не публикуйте их в GitHub.

## Простой путь: отдельный сервер Render

Для текущего подключения потребуется учётная запись Render и отдельный API-проект OpenAI с доступной моделью и оплатой. Расходы на хостинг, диск и API проверяются в их кабинетах. Платёжные обязательства автоматически не создавались.

### 1. Подготовить репозиторий сервера

Создайте отдельный, желательно приватный репозиторий с выбранным вами названием, например `finance-os-ai`. Это **не замена** существующему репозиторию `finance-os`. В него загрузите содержимое `FINANCE_OS_4_0_AI_Server.zip`: `main.py`, `manage.py`, `requirements.txt`, `render.yaml` и служебные файлы.

Не загружайте сюда личную JSON-базу, настоящий `.env`, `auth.sqlite3` или любые ключи. В `.env.example` приведены только названия настроек и пустые значения.

### 2. Развернуть сервис

В Render создайте Web Service из этого репозитория:

| Настройка | Значение |
|---|---|
| Runtime | Python 3 |
| Build command | `pip install -r requirements.txt` |
| Start command | `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1 --no-access-log` |
| Health check path | `/v1/health` |
| Persistent disk | каталог `/var/data` |
| Число экземпляров | 1 |

Постоянный диск необходим для кодов доступа, сессий и счётчиков лимитов. В Render он требует совместимого платного сервиса; без диска данные файловой системы могут пропасть при перезапуске. Финансовые записи пользователя здесь не хранятся.

В архиве есть необязательный `render.yaml`. Он описывает один платный сервис с диском; **перед запуском Blueprint проверьте тариф и подтвердите стоимость в Render**. Шаблон сверялся с документацией, но фактическое размещение не выполнялось. При создании через Blueprint репозиторий используется текущий; секреты запрашиваются отдельно.

### 3. Задать переменные на сервере

Откройте Environment в Render и заполните:

| Имя | Что указать |
|---|---|
| `OPENAI_API_KEY` | Ваш секретный серверный ключ API, только здесь |
| `OPENAI_MODEL` | ID доступной вам модели с Responses API и строгим JSON Schema |
| `ALLOWED_ORIGINS` | `https://marklanskoy.github.io` — без `/finance-os/` |
| `AUTH_DB` | `/var/data/auth.sqlite3` |
| `USER_DAILY_LIMIT` | Например, `30` |
| `GLOBAL_DAILY_LIMIT` | Например, `200` |
| `GLOBAL_MONTHLY_LIMIT` | Например, `3000` |

`OPENAI_MODEL` намеренно не зашит в код: используйте модель, реально доступную вашему API-проекту. Скопируйте точный ID из кабинета провайдера и проверьте поддержку Responses/Structured Outputs. Неподдерживаемая модель вернёт понятную ошибку, а не фиктивный ответ. `OPENAI_REASONING_EFFORT` оставьте пустым, пока не проверите, что выбранная модель принимает этот параметр.

Сохраните переменные и перезапустите/разверните сервис. Адрес будет вида `https://ваш-сервис.onrender.com`. Откройте `/v1/health`: при заданных ключе и модели поле `configured` станет `true`. **Это только наличие настроек, а не проверка баланса API, работоспособности модели или успешного финансового ответа.**

### 4. Создать личный код доступа

В Shell именно этого работающего сервиса выполните:

```bash
python manage.py create-user --label owner
```

Сохраните показанные `User ID` и `Personal access code` в безопасном месте. Код выводится при создании; в серверной базе остаётся только его хеш. Он даёт доступ к оплачиваемому вами API через этот сервер — не публикуйте его в HTML или общей инструкции.

Для каждого тестировщика создайте отдельный код. Его можно отозвать:

```bash
python manage.py list-users
python manage.py revoke-user USER_ID
```

При отзыве блокируются также действующие сессии. Не вставляйте код или секрет провайдера в общедоступный терминальный лог/скриншот.

### 5. Подключить FINANCE OS

В опубликованном FINANCE OS 4.0 откройте:

**Помощник → Подключение ИИ.**

Введите URL сервера и личный код доступа. После успешной проверки переключится индикатор режима. Перед первым запросом проверьте сводку и подтвердите согласие на её передачу.

Напишите: **«Распредели свободный остаток. Оставь мне 30 000 на личные решения»**. Сумма приведена только как пример команды. Помощник использует вашу базу, настройки и цели. До отдельного нажатия «Применить план» ничего не распределяется.

Настройка финансового профиля и «Моих правил» всё равно нужна: нейросеть не может узнать не внесённые расходы. Пустые цели нужно создать самостоятельно. Переписка может предлагать приоритеты, но не создаёт долг, банковский платёж или резерв без записей и подтверждения.

Сессия действует до 6 часов на сервере, но не сохраняется при закрытии/перезапуске вкладки. После повторного открытия может потребоваться личный код. Это сознательный режим закрытой беты, не полноценный облачный аккаунт.

## Локальный запуск сервера для разработчика

Требуется Python 3.12+; проверки выполнялись на 3.13.5. Из папки `server` полного исходника или корня отдельного AI-Server:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
export AUTH_DB="$PWD/private/auth.sqlite3"
export ALLOWED_ORIGINS="http://127.0.0.1:8765,https://marklanskoy.github.io"
# OPENAI_API_KEY и OPENAI_MODEL задайте в окружении приватно, не в общем скрипте.
python manage.py create-user --label local-owner
python -m uvicorn main:app --host 127.0.0.1 --port 8787 --workers 1 --no-access-log
```

На Windows активируйте `.venv\Scripts\Activate.ps1` и задайте переменные через `$env:ИМЯ`. Программа не читает `.env` сама: файл-пример не является настройкой окружения. В production используйте HTTPS; HTTP разрешён только для локальной разработки.

Готовый фронтенд разрешает AI-домены `*.onrender.com`, `*.workers.dev`, свой origin и `http://127.0.0.1:8787`. Workers указан в CSP как допустимое размещение совместимого API, но **готовый сервер — Python/FastAPI, не Cloudflare Worker**. Для другого домена пересоберите фронтенд: `AI_ORIGIN=https://api.example.com node build.mjs`.

Dockerfile также приложен, но Docker-сборка в этой среде не запускалась. Для него смонтируйте постоянный каталог `/data`, доступный пользователю UID 10001. Для Render с Python используется `/var/data`, как описано выше.

## Что отправляется и что хранится

Финансовая база остаётся на устройстве. С согласия сервер получает сводку сумм/сроков, псевдонимы счетов и целей, до трёх месячных сводок категорий и текст текущего запроса с несколькими последними сообщениями. Названия операций/магазинов и полные сырые транзакции автоматически не прикладываются. Текст, который вы сами напишете, тоже передаётся; не вводите секреты.

Текущий сервер хранит только хеши кодов/сессий, ID/подписи пользователей и счётчики запросов. Текст запроса и сводка обрабатываются в памяти и не пишутся в прикладную БД. Сервис запускается без access-log; проверьте также журналы и политику хостинга. SQLite с кодами не является зашифрованной финансовой базой.

Запрос OpenAI использует `store:false`. Это не обещание Zero Data Retention и не отмена всех правил журналирования провайдера. Условия обработки данных и возможного хранения приведены в официальной документации OpenAI. В UI есть отзыв согласия, очистка разговора и отключение ИИ.

## Лимиты и безопасность

Доступ по индивидуальному коду, короткая сессия, ограничения 5 запросов/минуту на пользователя и настраиваемые суточные/месячные квоты. Квоты обновляются атомарно в постоянной SQLite и не сбрасываются при обычном перезапуске. Ошибочный оплачиваемый запрос тоже может расходовать квоту. Это лимиты числа запросов, **не гарантия максимальной суммы счёта**. Контролируйте затраты и ограничения в кабинете API.

Без постоянного диска/при нескольких независимых экземплярах сервера защита квот не обеспечивает общий предел. Для масштабирования нужен общий транзакционный механизм квот/авторизации. Корректно настройте доверенные прокси на хостинге: код не доверяет произвольному `X-Forwarded-For`.

Сервер не имеет инструмента записи в финансовую базу. JSON модели дополнительно проверяется на стороне сервера и браузера. Схема ответа не гарантирует правильность рассуждений; пользователь должен сверять план. Доступ к банкам отсутствует.

Перед открытой публикацией: независимая проверка безопасности, нагрузочные испытания, требования к персональным/финансовым данным и пользовательская политика, восстановление серверной базы, собственные лимиты бюджета, мониторинг без лишних персональных данных. Этот пакет предназначен для личного использования и закрытой беты.

## Частые ошибки

| На экране | Что проверить |
|---|---|
| «Локальный расчёт · без ИИ» | Это нормальное состояние до подключения сервера, а не скрытая нейросеть |
| «ИИ ещё не настроен» | Ключ/модель в Environment сервера, не в GitHub Pages |
| «Код неверный» | Личный код из `manage.py`; API-ключ OpenAI сюда не вводится |
| «Лимит исчерпан» | Квоты сервера и API-проект, не повторять запрос бесконечно |
| «Источник не разрешён» | В `ALLOWED_ORIGINS` домен фронтенда без пути; после смены настройки перезапустите сервис |
| `Failed to fetch` | HTTPS, адрес, работоспособность сервера и CSP; для собственного домена нужна пересборка |
| «Нужно уточнить данные» | Финансовый профиль, реальные остатки, обязательства, правила помощника |
| «План устарел» | Записи/дата изменились или прошло 10 минут; получите новый расчёт |
| После обновления пусто | Не вводите доходы заново. Проверьте прежний браузер/адрес, сохраните копии и восстановите исходный JSON |
