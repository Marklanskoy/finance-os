# FINANCE OS 3.0 — Навигатор

Готовое обновление существующего FINANCE OS 2.0. Локальное веб-приложение для личных финансов: журнал, счета, бюджеты, цели и новые сценарии планирования. Дата выпуска файлов: 12 октября 2026 года. Это не банковское приложение и не гарантия допустимости покупки.

## Установить с iPhone без редактирования кода

1. **До загрузки обновления** откройте прежний FINANCE OS в привычном браузере. «Ещё → Скачать резервную копию». Сохраните JSON в «Файлы» отдельно от архива приложения. Не публикуйте эту копию.
2. Распакуйте `FINANCE_OS_3_0_Update.zip`. Откройте существующий репозиторий `Marklanskoy/finance-os` → **Add file → Upload files**.
3. Загрузите **содержимое архива в корень**, заменяя одноимённые файлы. Не загружайте сам ZIP и не создавайте внешнюю папку. `index.html`, `sw.js`, `update.html`, манифест и иконки должны лежать рядом. Основной код и стили уже встроены в `index.html`; папок JavaScript нет.
4. Нажмите **Commit changes**. Оставьте прежний адрес сайта и настройки Pages: `main`, `/(root)`. Дождитесь успешной публикации.
5. Закройте другие вкладки и установленную на домашний экран версию FINANCE OS. В том же браузере откройте:
   `https://marklanskoy.github.io/finance-os/update.html`
6. Нажмите **«Открыть FINANCE OS 3.0»**. Страница проверит наличие новой версии и обновит файлы, не очищая базу. Номер версии виден в «Ещё» и в Навигаторе.
7. Сверьте счета и последние операции. Затем откройте **«Навигатор → Профиль»**: настройте период, обычные расходы сверх календаря и внесите предстоящие обязательства. Сделайте новую внешнюю JSON-копию.

Адрес выше — адрес для перехода **после вашей публикации**. Этот архив не был автоматически загружен в репозиторий.

**Нельзя очищать данные сайта, localStorage или IndexedDB для обновления.** Не создавайте новый репозиторий и не меняйте домен/путь: локальная база привязана к браузеру, origin и пути приложения. Приватная вкладка и другой браузер не видят прежних записей. Не загружайте личные JSON-копии на публичный GitHub.

Если до обновления вы уже очистили браузер, серверной копии у приложения нет. Для восстановления потребуется ранее экспортированный JSON.

## Что добавлено

| Система | Как пользоваться |
|---|---|
| Проверка покупки | Введите сумму, счёт и дату. Получите результат по свободным деньгам, резервам и внесённым обязательствам. Проверка не записывает расход. |
| Финансовый календарь | Просмотрите остатки по дням, будущие платежи и нехватку на отдельных счетах. Ожидаемые доходы включаются в сценарий отдельно. |
| Стресс-сценарии | Проверьте задержку дохода, его снижение или дополнительную покупку, не меняя записи. |
| Переносы и перекрытия | Перенесите остаток лимита из прошлого месяца или из другой категории. У переноса есть история; он не увеличивает деньги на счетах. |
| Запас бюджета | Назначьте имеющиеся средства запасу. При покупке отдельно подтвердите использование недостающей суммы. |
| Распределение зарплаты | Выберите уже полученное поступление, подставьте собственные взносы из целей или укажите суммы. Повторное распределение той же записи заблокировано. |
| Стабилизатор «Своя зарплата» | Для нестабильного личного дохода: в удачный период создавайте буфер, в слабый — выделяйте из него средства. Будущая выручка не считается заработанной. |
| Редкие плановые расходы | Создайте копилку с полной суммой и датой оплаты. Календарь учитывает уже выделенные средства без двойного вычитания. |
| Подушка во времени | Укажите необходимые месячные расходы и наполните отдельную экстренную копилку. Показывается приблизительное количество месяцев без дохода. |
| Подписки и регулярные счета | Месячные, годовые и недельные правила, напоминания, годовая стоимость. Факт оплаты нужно подтвердить или связать с уже внесённой записью. |
| План погашения долгов | Сравните «лавину» и «снежный ком» по введённой номинальной ставке и полному минимальному платежу. Реальный остаток долга не меняется. |
| Список желаний | Сохраните покупку, задайте собственный посильный взнос и проверьте сценарий срока. Желание само не резервирует деньги. |
| Один гибкий лимит | Общий лимит на выбранные категории желаний за зарплатный период. Он показан отдельно от фактической доступности средств. |
| Разбор недели | Сравнение покупок за вычетом возвратов и короткие объяснения по внесённым данным. Нет выдуманного «балла финансовой свободы». |

Это локальные расчётные системы, **не подключённая нейросеть**. Тексты объяснений формируются правилами. Данные не отправляются внешним AI-сервисам.

## Первые пять минут

В Навигаторе настройте профиль. В «Регулярных платежах» добавьте только ещё не внесённые ближайшие счета. Затем создайте «Запас бюджета» и подтвердите выделение денег на существующем счёте. Вернитесь в «Проверить покупку», укажите сумму — сначала посмотрите последствия. Перенос из резерва и запись плановой покупки являются двумя отдельными действиями.

Не нужно заполнять все разделы сразу. Журнал и прежние функции работают без настройки Навигатора. Без подтверждённого профиля проверка покупки показывает, что информации недостаточно.

## Как читать суммы правильно

**Баланс** — фактические деньги по внесённым операциям и остаткам, а не обещанная зарплата и не кредитный лимит.

**Свободно по плану Навигатора** = баланс − все фактически выделенные копилки − непокрытая копилками часть календарных платежей − внесённая оценка обычных трат до конца горизонта − выбранный неприкосновенный остаток. Будущие поступления не прибавляются. Это не банковский доступный остаток.

Обычные расходы «в день» указывайте **сверх** отдельных платежей календаря. Деньги на ту же покупку нельзя вычитать как отдельный платёж и как ежедневную потребность. Месячные необходимые расходы для подушки используются только для её срока; в свободный остаток второй раз не вычитаются.

**Перенос лимита** меняет план, не деньги. Входящий перенос уменьшает исходящий лимит источника. Несколько переносов из прошлого месяца проверяются совместно по нынешнему свободному остатку. Исходные лимиты и история остаются видимыми. Лимиты не являются полностью профинансированными конвертами: для реальной покупки нужна отдельная проверка средств.

**Распределение и освобождение резерва** меняет назначение существующих средств. Это не банковский перевод, не доход, не второй расход. Экстренная подушка не предлагается для обычной покупки. Освободить её можно только отдельным явным действием пользователя.

**Два режима прогноза**: без будущих доходов (по умолчанию) и с ними (явное предположение). Прогноз проверяет дневные остатки, а не точный порядок банковских списаний внутри дня. Расходы на жизнь списываются в модели из общего пула; конкретный счёт для них автоматически не угадывается. При недостатке на счёте платежа требуется фактический перевод и его запись в журнал.

## Ограничения, важные для финансовых решений

- Банки, облачная синхронизация, фоновый push, реальные автоматические переводы, инвестирование и LLM не подключены.
- Все выводы основаны на внесённых пользователем данных. Самоподтверждение сверки не равно банковской проверке. По истечении недели приложение просит уточнить профиль.
- Одна валюта на базу: KZT, RUB, USD или EUR; нет мультивалютных счетов и конвертации.
- PIN только скрывает интерфейс. Локальная база, черновики, резервные копии и экспорт **не зашифрованы**. Берегите устройство и отдельно скачанные файлы.
- Подписка в приложении — напоминание. Пауза или пропуск не отменяет договор с сервисом. Неподтверждённые платежи правил за последний год считаются просроченными; более ранние обязательства нужно внести вручную. Дату начала правила выбирайте по первому ещё не учтённому платежу.
- Долги из «Обязательств» уже попадают в календарь. Не создавайте дублирующее правило для того же платежа. Без дополнительных параметров учитывается основной платёж, проценты добавляйте в план. После ввода параметров выводится оценка полного платежа.
- Сравнение долгов — упрощённая модель: постоянная номинальная годовая ставка / 12, начисление раз в месяц, округление до минимальных единиц, платёж в конце месяца. Не используйте ГЭСВ вместо номинальной ставки. Дневные проценты, комиссии, льготы, штрафы и договорные правила досрочного погашения не моделируются. Сверяйте договор и график кредитора. Дополнительный платёж не проверяется автоматически на доступность — используйте календарь.
- Срок желания или цели — сценарий по выбранному взносу, без роста цены и инвестиционной доходности. Каждое желание оценивается отдельно; один остаток нельзя потратить на все желания одновременно.
- Зарплатное распределение подставляет максимум два назначения за один проход из ваших целей и сроков. Это не автоматический банковский платёж и не универсальная рекомендация процентов дохода.
- Резерв уменьшился — финансовая устойчивость уменьшилась. Постоянное использование запаса не увеличивает доход.
- Выпуск прошёл автоматические и DOM-модельные проверки, но не полноценный аудит безопасности или проверку на физических iPhone/Android. См. `TEST_REPORT.md` в исходниках.

## Совместимость и восстановление

База сохраняет имя `finance-os-v2:<путь приложения>`, отдельно для демо. Основная схема данных остаётся 2; новый раздел `navigator` добавляется по необходимости, существующие счета, операции, цели и долги не заменяются. Версия самого IndexedDB поднимается с 1 до 2, чтобы старый клиент не писал параллельно в расширенные данные.

При обновлении существующего IndexedDB перед изменениями создаётся отдельный локальный снимок `before-navigator-3`. Его можно скачать из «Ещё → История восстановления». Это не замена внешнему JSON: если удалён весь сайт из браузера, удалятся и локальные снимки.

Импорт принимает проверенную базу версии 2.0, базу 3.0 или исходную старую структуру через сохранённую миграцию. Встроенная отмена доступна только для последнего успешного изменения при неизменной ревизии. Сохраняются также пять последних локальных снимков. Не пытайтесь открыть старый HTML-клиент после повышения версии базы: используйте новый клиент и внешнюю копию.

## Для разработчика

ZIP обновления — уже собранные файлы. Node.js на GitHub Pages не требуется. ZIP исходников содержит `src/`, `public/`, `tests/`, `dist/`, `build.mjs` и протокол проверки.

Локальная сборка (проверено на Node.js 22.16.0):

```bash
node build.mjs
node --test tests/core.test.mjs tests/store.test.mjs tests/package.test.mjs tests/navigator.test.mjs
python3 -m http.server 8000 --directory dist
```

Откройте `http://127.0.0.1:8000/` в своём браузере. Для тестовых данных — `?demo=1`. Самостоятельное открытие HTML через предпросмотр «Файлов» на iPhone не является поддерживаемым способом запуска.

Тесты интерфейса требуют Python, Playwright и Chromium. Модельные тесты намеренно подменяют хранилище; они не доказывают работоспособность настоящего IndexedDB или service worker. CSP и модель кеширования проверяются отдельно.
