# FINANCE OS 4.0 — Финансовый помощник

**Обновление существующего FINANCE OS, а не новая база.** Дата подготовки: 12 октября 2026 года. Исходная версия: `Marklanskoy/finance-os`, Git blob `238309552b5c866b2565a6412cfa0d66604f6329`.

## Главное до установки

В выпуске есть **два явно разных режима**:

- **Локальный расчёт — без ИИ.** Уже предлагает распределение всего свободного остатка по вашим целям и правилам. Работает без API-ключа. Ограниченные текстовые команды не выдаются за нейросеть.
- **Внешний ИИ.** В комплекте настоящий серверный адаптер OpenAI Responses API: понимание запросов, уточнения, подготовка проверяемого плана. Он заработает только после развёртывания сервера, настройки модели и API-ключа владельцем. Сервер не развёрнут автоматически и платные запросы при подготовке выпуска не выполнялись.

**Загрузка ZIP на GitHub Pages обновляет интерфейс, но не включает облачный ИИ.** Для свободного диалога нужен отдельный AI-Server. Не вставляйте секрет OpenAI в HTML, приложение или чат.

## Установка без потери прежних расходов

1. В прежней версии, в том же браузере, откройте **«Ещё → Скачать резервную копию»**. Сохраните личный JSON отдельно. НЕ публикуйте этот файл на GitHub.
2. Распакуйте `FINANCE_OS_4_0_Update.zip`. Загрузите **все файлы из него в корень существующего репозитория `finance-os`**, заменив одноимённые. Не загружайте ZIP и не добавляйте внешнюю папку.
3. Сохраните прежний адрес сайта. Нажмите **Commit changes** и дождитесь успешного размещения GitHub Pages. Этот выпуск не был отправлен в репозиторий из данной среды: GitHub дал доступ только на чтение.
4. Закройте все старые вкладки и установленную на домашнем экране версию. В привычном браузере откройте `https://marklanskoy.github.io/finance-os/update.html` и нажмите **«Открыть FINANCE OS 4.0»**. Эта ссылка предназначена для перехода после вашей публикации файлов.
5. Проверьте, что в «Ещё» отображается 4.0.0, а ваши счета и последние операции сохранились. Скачайте новую внешнюю копию.

**Не очищайте Safari/Chrome, IndexedDB или localStorage. Не создавайте новую личную базу поверх старой. Не открывайте старый клиент параллельно с новым.** Приватная вкладка и другой браузер не увидят прежние записи. Предпросмотр `index.html` в приложении iPhone «Файлы» не является поддерживаемым запуском: используйте опубликованный сайт.

Имя базы сохранено: `finance-os-v2:<путь приложения>`. Данные прежних версий не копируются в новый независимый кошелёк; добавляется раздел `assistant`. Основная схема остаётся 2, версия самого IndexedDB повышается до 3, чтобы старый клиент не писал параллельно. При обновлении предусмотрен снимок `before-assistant-4`; его можно скачать через **«Ещё → История восстановления → Скачать базу до обновления 4.0»**. Это локальная страховка, не замена внешнему JSON.

Импорт 2.0/3.0/4.0 сохраняется. Он **заменяет** выбранную базу, а не объединяет истории. При уже видимых старых операциях импортировать копию повторно не нужно. При ошибке не очищайте данные: сохраните JSON для восстановления.

## Где теперь функции

Основные вкладки: **Главная · Помощник · Операции · Бюджет · Цели · Ещё**.

Прежние инструменты не удалены. Календарь, переносы лимитов, регулярные платежи, стабилизатор дохода, подушка, долги и список желаний находятся в **«Ещё → Финансовый навигатор»**. Главный экран дополнен кнопкой **«Предложить план»**.

В Помощнике три основных действия:

| Действие | Что делает | Чего не делает |
|---|---|---|
| Распределить деньги | Подготавливает назначения для всех целей из одного свободного остатка | Не создаёт зарплату и не переводит деньги в банке |
| Проверить покупку | Проверяет сумму, счёт, дату и сценарий остатка | Не оплачивает и не записывает расход автоматически |
| Исправить план | Предлагает покрытие нехватки из обычного запаса | Не трогает экстренную подушку и защищённые цели |

## Первые пять минут: остаток 72 000 ₸

72 000 ₸ здесь — учебный пример. В личной базе используйте фактические данные.

**1. Проверьте исходные данные.** Помощник → «Что учтено». Он вычитает из реальных денег копилки, непокрытую часть календарных платежей, обычные траты до указанного горизонта и неприкосновенный остаток. Будущая зарплата не прибавляется. Невнесённые траты программа не знает.

**2. Откройте «Мои правила».** Укажите, сколько хотите оставить свободными сверх обычных расходов; при необходимости выберите главную цель и защитите обычный запас от использования. Отсутствие отдельного приоритета означает порядок «резерв → даты целей», а не универсальную финансовую рекомендацию.

**3. Нужны реальные назначения.** В «Целях» должны быть ваши цели/взносы; в Навигаторе можно создать запас. Пустую базу помощник не заполняет придуманными финансовыми целями. Сумма цели — желаемый уровень, а не уже накопленные деньги.

**4. Нажмите «Распределить деньги».** Предложение покажет каждую сумму, счёт-источник, причину, все цели вместе и остаток после. Например, если из свободных 72 000 ₸ по вашим правилам нужно 20 000 ₸ в запас и 30 000 ₸ на цель, 22 000 ₸ останутся свободными. Это не фиксированные проценты: при других целях результат будет другим.

**5. Измените план или подтвердите.** «Изменить суммы» позволяет задать точные назначения. Команда локального режима «Оставь мне 30 000» пересчитывает личный остаток. Кнопка «Применить план» показывает отдельное подтверждение и только затем меняет назначения. Банковский баланс остаётся прежним.

Нераспределённые деньги не нужно вносить новым доходом. Распределение работает с общим остатком, даже если он получен из нескольких зарплат и прошлых периодов. Уже выполненные взносы этого периода учитываются, чтобы не предлагать их повторно.

## Настоящий ИИ: что меняется после подключения

Откройте **Помощник → Подключение ИИ**. Введите адрес вашего сервера и личный код бета-доступа. Это не OpenAI API-ключ. Подробный запуск описан в `AI_SETUP.md`.

Перед первым финансовым запросом появится «Что отправится внешнему ИИ»: сводка сумм, сроков, обезличенных обозначений целей/счетов и предупреждение о передаче текста разговора. Никакой запрос финансового плана не отправляется до согласия. Чат и финансовая сводка не должны содержать пароли, ИИН, номера карт и коды подтверждения.

После подключения доступны свободные формулировки в рамках поддерживаемых задач, например:

> «Предложи распределение остатка. Оставь мне 30 000, остальные деньги сначала направь в запас».
>
> «В этом месяце хочу больше свободных денег. Как изменится план?»
>
> «Я потратил больше обычного. Можно покрыть нехватку из запаса, не трогая подушку?»

Нейросеть возвращает ограниченное структурированное предложение. Денежные расчёты и допустимость применения перепроверяет программа. ИИ не умеет записывать произвольный код, удалять операции, получать кредит или совершать платежи.

**Разовое изменение и постоянное правило разделены.** Вариант из разговора не переписывает ваши предпочтения. После изменения может появиться «Запомнить правило» с отдельным подтверждением. Список правил доступен и редактируется.

Если сервер или модель недоступны, отображается ошибка. Приложение не выдаёт локальный текст за успешный ответ ИИ. Обычный учёт и явно выбранный локальный режим остаются доступны.

## Что проверяет новый расчётчик

- Один общий пул денег для всех целей. Остаток не используется несколько раз для разных желаний.
- Деньги — целые минимальные единицы валюты; расчёт не основан на неточных дробных суммах.
- Назначение не может превышать свободный остаток после личной суммы, остаток цели и возможность конкретного счёта после его платежей.
- Создание черновика, проверка покупки и стресс-сценарий не изменяют базу.
- План привязан к ревизии записей, текущему дню и сроку 10 минут. После изменения данных нужен пересчёт.
- Повторное применение одного плана блокируется. Сохранение атомарное; история и назначения меняются вместе.
- При покрытии используется только обычный бюджетный запас. Нехватка, которую он не покрывает, остаётся видимой.
- Копилка связанного календарного платежа не вычитается второй раз: итог после плана вычисляется на копии состояния.
- Имеются причины сумм, история до/после и отмена последнего успешного действия при неизменной ревизии.
- Отсутствующая или устаревшая сверка не выдаётся за подтверждённую финансовую информацию.

## Что сохранено из 3.0

Счета, расходы/доходы, возвраты, переводы с комиссией, плановые операции, бюджеты конкретных месяцев, цели, долги, регулярные платежи, переносы и перекрытия, «Своя зарплата», копилки к дате, сценарии погашения, список желаний, отчёты, PIN, внешние копии и локальная история восстановления. Светлая и тёмная темы поддерживаются.

Новая функция использует прежние цели и резервы. Не создавайте второй одинаковый резерв только потому, что он виден и в Навигаторе, и в «Целях».

## Важные ограничения

1. **Внешний ИИ не активирован.** Нужны сервер, действующий ключ, доступная совместимая модель и оплата провайдера. Подписка ChatGPT не заменяет оплату API.
2. **Нет банков, облачной синхронизации и автоматических переводов.** Сервер ИИ не является резервной копией финансовой базы.
3. **Это бюджетная бета, не лицензированный финансовый управляющий.** Нет инвестиционных рекомендаций, гарантии доходности, кредитных продуктов и автоматического исполнения. При неполных записях вывод может быть неверным.
4. **Все цели учитываются совместно для текущего распределения.** Помощник не строит полноценную совместную многолетнюю оптимизацию доходов, долгов и всех покупок. Сроки старого списка желаний по-прежнему условные и не обещаны ИИ.
5. **Исправить план** покрывает внесённую нехватку обычным запасом. Перенос лимита категорий и сокращение будущих взносов можно выполнить в прежнем Навигаторе; ИИ не меняет произвольно уже защищённые деньги. Известные покупки уже должны быть внесены.
6. Прогноз по дням не моделирует точную очередь банковских списаний внутри дня. Будущие доходы — сценарий. Перевод между счетами нужно реально выполнить и записать отдельно.
7. Одна валюта на базу. Чат в этой версии на русском; нет банковской мультивалютной конвертации.
8. PIN скрывает интерфейс, но **не шифрует локальную базу, черновики и JSON**. Серверные сессии хранятся в памяти вкладки и сбрасываются при закрытии/блокировке/отключении. Код доступа нужно беречь.
9. История решений и правила сохраняются в общей базе. Переписка не сохраняется между закрытиями вкладки. Она может передаваться провайдеру в текущем сеансе после согласия; это не обещание отсутствия хранения у провайдера.
10. Сводка ограничена 80 целями, 30 счетами и 80 ближайшими событиями. При превышении лимита удалённое планирование просит уточнение, а не молча делает уверенный вывод по усечённым данным.
11. Сервер подготовлен для **закрытой беты**, не публичного сервиса с неограниченной регистрацией. Для массового выпуска нужны полноценная авторизация, эксплуатационный мониторинг, юридическая/приватностная проверка и масштабирование.
12. При исправлении записей или импорте действующий план требуется пересчитать. Внешний JSON заменяет базу, не объединяет операции.
13. Настоящий IndexedDB, установленная PWA, физический iPhone, развёртывание Render/Docker и платный ответ OpenAI не проверены в данной среде. См. `TEST_REPORT.md`.

## Для разработчика

```bash
node build.mjs
node --test tests/*.test.mjs
python -m pip install -r server/requirements.txt
(cd server && python -m unittest -v test_api)
python -m http.server 8765 --directory dist
```

Откройте локальный адрес `http://127.0.0.1:8765/` в своём браузере. Для демобазы — `?demo=1`. Native URL smoke test: `python tests/smoke.py`; DOM-модели: `python tests/browser_model.py`, `python tests/navigator_ui.py`, `python tests/assistant_ui.py` (Playwright + Chromium).

Готовый `index.html` содержит код и стили. Сборщик обновляет CSP-хеш и версию кэша. После изменения исходников пересоберите, не редактируйте встроенный JavaScript без обновления CSP. Для своего домена ИИ: `AI_ORIGIN=https://api.example.com node build.mjs`.

История в GitHub не менялась при подготовке. ZIP исходников включает код веб-приложения, сервер, тесты и отдельные результаты проверок. README и Release отличают выполненные тесты от требований внешнего подключения.
